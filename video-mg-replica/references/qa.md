# 对照验收

验收对象是整个请求范围，包括所有镜头和音频。初次静态、动态初版及每轮修正分别输出目录，避免旧证据和新源码混用。

## 技术与像素证据

compare 要求两文件显示尺寸、解码帧数和平均 fps 一致，不会自动裁切、缩放或平移来掩盖问题。确认两输入本身是 CFR 且以同一时间起点开始；VFR 先使用 inspect。对不同颜色空间、HDR 或不同像素宽高比先统一且记录处理，不把颜色管理偏差误判为设计颜色错误。

默认每 10 帧抽样，仅报告 RGB MAE、最大通道误差和差异像素比例；这些是采样辅助数据，不是全片相似度。`--step 1` 可以遍历全部帧，但文件数量和计算量随时长增加。无论数据多好都要看图。原始 MP4 压缩、字体抗锯齿会造成非零差异，不设一个百分比自动宣布通过。

triptych 左原片、中复刻、右增强差异；对照视频左原片、右复刻，底部有 REF/REPLICA 标签。对照视频使用复刻音轨（若有）；用它判断节奏，另外比较 source/audio.wav 和成片音轨。不要把 reference.mkv 无音轨误当作请求静音。

## 人工检查项

| 项目 | 证据/判断 |
|---|---|
| 技术 | 尺寸、fps、帧数、首尾和请求范围一致；没有丢帧/意外黑场 |
| 静态 | 每场落定帧：比例、对齐、字体/换行、线宽、颜色、遮挡 |
| 运动 | 入场/退出时刻、动作中途位置、曲线、路径方向、转场前后 1 帧 |
| 音频 | 配音未截断、音乐/音效与视觉对齐，首尾时长一致；正常速度听审 |
| 可编辑性 | 改字/数字/图片后实际 still 变化；字图线是独立层，非整帧截图 |
| 复现 | 工程源码、props、锁文件、素材列表及渲染命令齐全 |

在 qa.md 中分别写状态、查看的帧/时间、证据路径与具体观察；没做的为 pending。只交付可编辑 MG 时允许人物层为复用实拍，但不能声称人物也被参数化。真实素材缺失、字体近似、复杂 3D/粒子未重建应列入已知差异。

## 修正顺序

先检查对齐的范围/帧号 → 大布局/字体 → 动作时机/路径/曲线 → 颜色/材质 → 微小纹理。每轮只修证据支持的问题；保存修前与修后的同一帧。默认两轮后仍不达标，保留 failed/pending 项并交付当前结果与缺口，不能靠改状态达到“通过”。
